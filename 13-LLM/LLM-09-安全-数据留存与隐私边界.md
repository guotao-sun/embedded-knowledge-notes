# 大模型服务的数据留存与隐私边界

## 一、先说结论

云端语音转写确实存在隐私风险，但风险的大小和你想象的机制不太一样。先把三件事分清：

1. **官方承诺"不用于训练"，不等于"不存储"**
2. **音频比文本更危险**，因为它没法脱敏
3. **真正最现实的漏洞，往往是你自己的服务**

## 二、留存期限的真相

### "保留 6 个月"这个说法从哪来

它来自《网络安全法》对**网络日志**的最低留存要求（不少于六个月）。这条规定管的是访问日志，不是你的音频内容，但经常被当成"厂商会存你 6 个月"的依据传开。

### 官方实际口径

翻服务协议和隐私政策，能确认的是：

- 不将用户数据用于模型训练
- 传输加密、存储加密
- 按"达成本协议目的所需期限"保留，超期删除（备份可能有延迟）
- 会按法律法规要求留存并配合监管调取

**没有任何条款承诺"6 个月后一定删"**。期限不公开，就意味着不可验证。

唯一明确承诺删除原始语音的是**声音复刻**这类场景，因为它是明确声明的"用完即弃"。

## 三、为什么音频比文本危险得多

### 两个维度的泄露

| 维度 | 文本 | 音频 |
|---|---|---|
| 内容 | 可以脱敏：人名→`[A]`、公司→`[公司1]` | **无法脱敏**，声音本身就是信息 |
| 身份 | 需要额外关联才能定位到人 | **声纹即生物识别信息**，属于敏感个人信息 |

声纹的法律属性很关键：它能唯一识别自然人，属敏感个人信息。而一段会议录音里往往有多个第三方，**你根本不可能取得他们的同意**，所以"用户已同意上传"这个说法在多人的场景下是站不住的。

### 一个具体例子

一段 40 分钟的内部技术评审：

- 上云转写 → 内容（产品规划、客户名、报价）+ 声纹（说话人身份）同时交给了第三方
- 只上云整理文本 → 内容风险仍在，但声纹风险消失

差别就在"传音频"还是"传文本"这一步。

## 四、四档分级方案

按泄露面从小到大排：

| 档位 | 做法 | 泄露什么 | 适用 |
|---|---|---|---|
| 0 全本地 | 本地 ASR + 本地 LLM 整理 | 无 | 涉密、人事、合同、客户报价 |
| 1 本地转写 + 文本脱敏后上云 | 本地出文本，替换敏感实体，再送云端整理 | 脱敏后的内容（可能通过上下文反推） | **最实用的折中，日常会议默认选这档** |
| 2 音频上云 | 直接上传录音做转写 | 内容 + 声纹 | 公开内容、已获全员同意的对外会议 |
| 3 私有化部署 | 自建集群 | 仅内部可见 | 企业级合规要求 |

### 档位 1 的关键动作

顺序不能反：**先本地转写，再脱敏，最后上云**。

脱敏要做的不只是替换人名：

- 人名 / 手机号 / 身份证 / 银行卡
- 公司名、项目代号、产品型号
- 金额、报价、日期（组合起来可反推项目）
- 会议地点、部门名

替换后统一用占位符（`[PERSON_1]`、`[ORG_2]`），云端返回后再按映射表还原。映射表只存在本地。

### 本地转写质量问题怎么办

本地小模型错字多，是真实痛点，但不必靠"上云"解决：

1. **VAD 切段 + 整段离线识别**——比流式增量识别的准确率高，短片段边界错误更少
2. **换更强的本地模型 + 热词表**——把项目名、产品型号塞进热词，专有名词错误率能明显下降
3. **本地 LLM 术语纠错**——把转写文本和术语表一起给本地小模型，只让它改错字不改内容

## 五、比云端留存更现实的漏洞

### 自建服务没有鉴权

局域网自建 ASR 服务，监听 `0.0.0.0` 且没有 API key，意味着**同一网段内任何设备都能调用你的转写接口**：手机、访客、智能家居设备、被感染的笔记本。

这个风险比"厂商会不会存我录音"现实得多，因为：

- 攻击面在你家里，不受任何平台合规约束
- 没有审计日志，被调用了你也不知道
- 一旦有人批量上传，还能反查你的服务行为

最小修复：生成一个随机 key 写进配置、所有请求带 `Authorization` 头、服务端校验不过直接 401。

### 其他常被忽略的点

- **日志**：多数服务会把请求体写进日志文件。转写结果落盘，等于同一份敏感内容存了两份。
- **临时文件**：上传的音频、切片的 wav 常常留在临时目录不清理。
- **结果缓存**：为了"24 小时内可查结果"，把转写文本原样存在本地，等于建了一个没加密的语料库。
- **浏览器 / 客户端缓存**：手机端 App 的下载缓存也可能留存音频副本。

## 六、决策清单

接到"要不要上云"这个问题时，按顺序问自己：

1. 这段录音里有第三方吗？他们同意了吗？
2. 内容属于公开 / 内部 / 涉密哪一档？
3. 我需要的是"转写"还是"整理"？能不能只把文字送出去？
4. 云端那部分能不能接受"留存期限不可验证"这个事实？
5. 本地这条链路本身安全吗（鉴权、日志、临时文件）？

前四个决定走哪一档，第五个决定你现在就该动手修什么。
