# 用户态与内核态：三条进门的路

## 一、先说结论

CPU 用"特权级别"把世界切成两半：用户态只能碰自己的地址空间、只能执行普通指令；要碰硬件、改页表、开中断，必须进内核态。

进来的路只有三条：**中断、异常、系统调用**。前两条是被动的，最后一条是主动的。

进来不是免费的：要切栈、保存现场、必要时切页表，所以"能不能少进几次"是很多性能优化的出发点（用户态驱动、io_uring、零拷贝都在干这件事）。

## 二、为什么必须分

| 如果允许用户态直接干 | 后果 |
|---|---|
| 直接写外设寄存器 | 一个程序能把整个板子的时钟/电源配乱 |
| 直接改页表 | 能读写任何进程的内存，隔离失效 |
| 直接关中断 | 系统的实时性被单个进程绑架 |
| 直接执行特权指令 | 硬件层面直接不给你执行（会陷入异常） |

所以硬件层面就设了闸：ARM 用**异常模式 + 特权指令**，x86 用 **Ring 0~3**，RISC-V 用 **M/U/S 三级**。这不是软件约定，是 CPU 强制的。

## 三、三条路

| 方式 | 触发源 | 主动性 | 典型场景 |
|---|---|---|---|
| 中断 | 硬件外设 | 被动 | 按键、DMA 完成、网络收包、定时器 |
| 异常 | CPU 硬件检测 | 被动 | 缺页、非法指令、未对齐访问、除零 |
| 系统调用 | 用户程序执行特定指令 | **主动** | open/read/write/mmap/ioctl |

### 中断

外设拉中断线 → 中断控制器 → CPU 保存现场 → 跳进内核的向量。特点是**和当前执行的代码无关**，谁在跑都可能被打断。

### 异常

CPU 在执行指令时自己发现"这不对"，于是触发：

```text
程序犯错（或需要内核帮忙） → CPU 发现 → 触发异常（trap） → 进内核处理
```

最常见的异常是**缺页**（页表项有效位为 0，见 [页表](./KERNEL-11-内存-页表.md)）；其次是非法指令、未对齐访问（某些配置下）、除零。

注意缺页不一定是"错"：栈增长、写时复制、文件页首次访问都靠缺页来分配内存，属于**正常机制**。

### 系统调用

用户程序执行一条专门的指令主动"请求服务"：

| 架构 | 指令 | 调用号放在哪 | 参数放在哪 |
|---|---|---|---|
| ARMv7（32 位） | `svc #0` | r7 | r0–r6 |
| ARMv8（64 位，RK3568） | `svc #0` | x8 | x0–x5 |
| x86_64 | `syscall` | rax | rdi、rsi、rdx、r10、r8、r9 |

所以"系统调用"本质是**一次受控的异常**：指令本身触发异常，CPU 切到内核模式，内核按调用号查表跳到 `sys_xxx`。

## 四、ARM 的异常模式

ARMv7 有多种处理器模式，进内核就是切模式：

| 模式 | 用途 |
|---|---|
| `usr` | 用户态，普通代码 |
| `svc` | 管理模式，系统调用/复位后默认 |
| `irq` | 普通中断 |
| `fiq` | 快速中断 |
| `abt` | 访问异常（取指/数据 abort） |
| `und` | 未定义指令 |
| `sys` | 特权态但用用户态寄存器组（用于跑内核线程） |
| `hyp` | 虚拟化扩展 |

每种异常模式都有自己的 `SP` 和 `SPSR`（保存被中断时的 `CPSR`），所以"切模式"的同时就完成了"换栈 + 存状态"的一部分工作。

## 五、切进去的时候保存/恢复什么

| 内容 | 说明 |
|---|---|
| CPSR / SPSR | 当前状态寄存器 / 被中断时的状态，返回时用它恢复 |
| LR（返回地址） | 从哪条指令被打断，回来继续执行 |
| SP | 切到内核栈（每个进程有自己的内核栈） |
| 通用寄存器 | 由入口代码决定保存多少（见 [中断对比](./KERNEL-05-中断-imx6ull与STM32中断对比.md)） |
| 页表基址 | x86 切 CR3；ARM 用户态用 `TTBR0`，内核映射常驻 `TTBR1`，切进程只换前者 |

内核栈是"每进程一份"的：进程阻塞在系统调用里时，它的内核栈上留着整个调用链——这也是为什么内核栈很小（通常 8 KB / 16 KB）、内核代码要避免深递归。

## 六、对比总结

| 方式 | 触发源 | 主动性 | 典型场景 |
|---|---|---|---|
| 中断 | 硬件外设 | 被动 | 按键、DMA 完成、网络数据包 |
| 异常 | CPU 硬件检测 | 被动 | 缺页、非法指令、数据访问错误 |
| 系统调用 | 用户程序指令 | 主动 | 文件操作、内存映射、进程管理 |

## 七、进内核之后的两条硬约束

1. **不能直接解引用用户指针**。用户给的地址可能没映射、可能被换出、可能是恶意构造的。必须用 `copy_from_user()` / `copy_to_user()`：它们会检查地址合法性、处理缺页，失败返回未拷贝的字节数。
2. **内核态也可能被抢占**（除关抢占的临界区外）。所以内核代码里的共享数据照样要加锁（见 [并发与竞争](./KERNEL-08-并发-并发与竞争.md)），不能有"我在内核态，没人能打断我"的错觉。

## 八、两个常见误解

| 误解 | 实际情况 |
|---|---|
| 系统调用就是普通函数调用，只是在内核里执行 | 它有完整的特权级切换：换栈、存状态、查调用号表，开销远大于函数调用 |
| 进了内核态就能随便访问用户内存 | 现代 CPU 有 SMAP/PAN 等机制，内核直接访问用户页会报错，必须走 `copy_*_user` |
| 中断和系统调用是同一类 | 触发源、主动性、能否睡眠都不同：中断上下文不能睡，系统调用在进程上下文，可以睡 |

## 九、一句话总结

用户态到内核态只有三条门：**硬件敲门（中断）、CPU 发现问题（异常）、程序主动申请（系统调用）**；进门要换栈存现场，出门要恢复现场，这套"进出场"就是内核态开销的来源。
