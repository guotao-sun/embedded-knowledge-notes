# C 语言常见问题

## 一、先说结论

嵌入式 C 的 bug，八成落在这张表里：

| # | 坑 | 典型症状 |
|---|---|---|
| 1 | `free` 传了非 `malloc` 返回的指针 | 段错误 / 堆损坏 |
| 2 | 数组越界、少一/多一 | 莫名改坏了相邻变量 |
| 3 | 野指针 / 释放后继续用 | 随机崩溃，难复现 |
| 4 | 函数里 `sizeof(指针)` 当数组长度 | 拷贝只拷了 4 字节 |
| 5 | `strcpy`/`sprintf` 溢出 | 栈被踩，返回地址被改 |
| 6 | 有符号与无符号混比 | `-1 < 0u` 为假，循环不退出 |
| 7 | 未初始化变量 / 返回局部变量地址 | 值随机；调用后数据变垃圾 |
| 8 | `==` 比较浮点 | 明明相等却进不了分支 |
| 9 | 缺 `volatile` | 中断改了变量、主循环看不到 |
| 10 | 结构体对齐/打包没管 | 与协议/寄存器布局对不上 |

下面挑最容易被问、也最容易被踩的几条展开。

## 二、`free(ptr + 1)` 会怎样

```c
char *ptr = malloc(100);
free(ptr + 1);          /* 错：ptr+1 不是 malloc 返回的地址 */
```

**结果：未定义行为**——轻则 `abort`，重则堆结构被破坏，过一段时间在别的地方崩。

### 为什么 `free` 必须拿到"原样"的指针

glibc 的 `malloc` 并不是"返回一块裸内存"，它在**用户指针前面**放了一小段管理信息（chunk header），记录块大小、前后块、标志位：

```text
        ┌──────────────┬─────────────────────────────┐
        │ chunk header │  返回给用户的内存（ptr）      │
        │ size/prev... │                             │
        └──────────────┴─────────────────────────────┘
                     ↑
                  ptr 指这里
```

`free(p)` 做的事是：**从 `p` 往回减去 header 大小，得到 chunk 起点**，再读那里的 `size` 字段来决定怎么合并。

所以传 `ptr + 1` 时，`free` 会跑到 `ptr + 1 - header_size` 去读"size"——那个位置放的是**你的数据**，被当成 size 解析：

| 情况 | 后果 |
|---|---|
| `ptr + 1` 还在自己这块内存里 | 把用户数据当 size → 合并到错误地址 → 段错误或堆损坏 |
| `ptr + 1` 指向栈/常量区 | 完全无关的地址被当作 chunk → 破坏堆管理结构，之后 `malloc` 各种离奇失败 |

### 两种"看起来没事"的假象

1. **没立刻崩**：堆还没被写坏到关键位置，程序继续跑，几十分钟后在完全无关的地方崩——这种最难查。
2. **`free` 不报错**：glibc 只在部分情况检测（如 `free(): invalid pointer`），很多情况是静默破坏。

### 正确姿势

```c
char *p = malloc(100);
if (p == NULL) { /* 处理失败，嵌入式里必须处理 */ }
/* 用 p ... */
free(p);
p = NULL;            /* 防悬空指针：之后误用会立刻崩，而不是悄悄写坏 */
```

需要"偏移后释放"的场景，正确做法是**自己保存原始指针**：

```c
char *base = malloc(100);
char *data = base + 8;       /* 头部留 8 字节给自己用 */
/* ... 用 data ... */
free(base);                  /* 永远释放 base */
```

### 想确认自己有没有传错

```bash
# glibc 下会打印具体地址与原因
MALLOC_CHECK_=3 ./app
# 或
valgrind --leak-check=full ./app
```

`valgrind` 能直接告诉你"invalid free"，比事后猜快得多。

## 三、数组越界与"少一/多一"

```c
int buf[10];
for (int i = 0; i <= 10; i++)   /* 错：i==10 时越界写 */
    buf[i] = 0;
```

`i <= 10` 写到了 `buf[10]`——它可能是**紧挨着的另一个变量**（编译器按栈布局排列），于是"改 A 数组却把 B 变量改了"。

嵌入式里更隐蔽的形式：

```c
uint8_t rx[8];
memcpy(rx, src, len);           /* len 可能 > 8，来自外部输入 */
```

**凡是长度来自外部（协议、文件、用户输入）的拷贝，都必须先判断上限**：

```c
if (len > sizeof(rx)) len = sizeof(rx);
memcpy(rx, src, len);
```

## 四、`sizeof(指针)` 不是数组长度

```c
void send(uint8_t *data) {          /* 参数退化成指针 */
    size_t n = sizeof(data);        /* 错：得到 4 或 8 */
}

uint8_t buf[64];
send(buf);                          /* 期望 64，实际 4 */
```

**数组作为函数参数时退化为指针**，`sizeof` 再也拿不到元素个数。正确做法是**长度一起传**：

```c
void send(const uint8_t *data, size_t n);
```

或用宏（只对"真数组"有效）：

```c
#define ARRAY_SIZE(a) (sizeof(a) / sizeof((a)[0]))
```

`ARRAY_SIZE` 传指针时会算错，所以宏名里最好带 `ARRAY` 提醒。

## 五、`strcpy` / `sprintf` 溢出

```c
char name[8];
strcpy(name, user_input);       /* 长度不受控 → 栈溢出 */
```

栈溢出会踩到**函数返回地址**，表现是"函数返回时跳到乱七八糟的地址"（嵌入式里常见 `HardFault` / `Segmentation fault`）。

修法：

```c
snprintf(name, sizeof(name), "%s", user_input);   /* 有界，且自动截断 */
```

三个常被忽略的细节：

1. `strncpy(dst, src, n)` **不保证**结尾有 `\0`（`src` 比 `n` 长时没有），要手动补：
   ```c
   strncpy(dst, src, sizeof(dst) - 1);
   dst[sizeof(dst) - 1] = '\0';
   ```
2. `snprintf` 返回的是"**想要写多长**"，不是"实际写了多长"——判断截断要看返回值是否 ≥ size；
3. 格式化字符串不要直接传用户数据：`printf(user_str)` 会被 `%n` 之类利用，写 `printf("%s", user_str)`。

## 六、有符号 / 无符号混比

```c
int i;
for (i = 10; i >= 0; i--) { ... }        /* 正常 */

size_t n = 0;
for (n = 10; n >= 0; n--) { ... }        /* 死循环！n 是无符号，永远 >= 0 */
```

还有更阴的：

```c
if (-1 < 0u)        /* 假：-1 被转成无符号，变成 4294967295 */
```

规则：**有符号与无符号一起运算时，有符号会被转成无符号**。所以：

- 循环计数用 `int`，别用 `size_t` 做倒序；
- 比较长度时统一类型，或显式强转；
- 打开 `-Wall -Wextra` 会让编译器警告 `comparison of integer expressions of different signedness`，**别忽略这个警告**。

## 七、野指针、悬空指针、返回局部地址

```c
/* ① 野指针：没初始化就用 */
char *p;
strcpy(p, "hi");              /* p 指向随机地址 → 崩 */

/* ② 悬空指针：释放后继续用 */
free(p);
p[0] = 'a';                   /* use-after-free */

/* ③ 返回局部变量地址 */
char *get_name(void) {
    char buf[16] = "abc";
    return buf;               /* 函数返回后 buf 所在栈帧失效 */
}
```

三个修法：

```c
char *p = NULL;               /* ① 初始化 */
free(p); p = NULL;            /* ② 释放后置空 */
static char buf[16];          /* ③ 要返回就 static 或由调用者传入缓冲区 */
```

③ 的 `static` 有代价：不可重入、多任务共用同一块。更稳的是让调用者给缓冲区：

```c
void get_name(char *out, size_t n);
```

## 八、浮点不能用 `==`

```c
float a = 0.1f + 0.2f;
if (a == 0.3f) { ... }        /* 多半不成立 */
```

`0.1` 在二进制里是无限循环小数，累加后与 `0.3` 差几个 ULP。修法：

```c
#include <math.h>
if (fabs(a - 0.3f) < 1e-6f) { ... }
```

顺带一句：嵌入式里能用整数就别用浮点——定点数（放大 1000 倍存 `int`）更快也更可控。

## 九、`volatile` 到底什么时候必须加

```c
volatile uint32_t *reg = (uint32_t *)0x40021000;
uint8_t flag = 0;

void EXTI_IRQHandler(void) { flag = 1; }     /* 中断里改 */

int main(void) {
    while (!flag) { }                        /* 编译器可能优化成 while(1) */
}
```

编译器看到 `flag` 在循环里没人改，可能把它提到寄存器里、只读一次——于是中断里改了内存，主循环永远看不到。

三个必须 `volatile` 的场景：

| 场景 | 例子 |
|---|---|
| 内存映射寄存器 | `*(volatile uint32_t *)0x40000000` |
| 中断与主循环共享的变量 | 上面的 `flag`（还应加 `volatile` + 关中断保护） |
| 多任务共享的标志 | RTOS 里的 `g_stop` |

`volatile` **只保证"每次都真的读写内存"，不保证原子性**——共享的多字节变量仍需要临界区（关中断/互斥量）。

## 十、结构体对齐与"打包"

```c
struct pkt {
    uint8_t  type;      /* 1 */
    uint32_t len;       /* 4 */
    uint8_t  data[3];   /* 3 */
};
```

`sizeof(struct pkt)` 在 32 位 ARM 上通常是 **12**，不是 8——因为 `len` 要对齐到 4 字节边界，中间插了 3 字节填充，尾部又补 1 字节。

后果：**用它直接收发协议/写寄存器会错位**。两种修法：

```c
/* ① 按协议字节序手工序列化（最稳，推荐） */
uint8_t buf[8];
buf[0] = type;
memcpy(&buf[1], &len, 4);
/* 发 buf，不直接发结构体 */

/* ② 强制紧凑（GCC/Clang） */
struct __attribute__((packed)) pkt { ... };
```

`packed` 的代价：非对齐访问在某些架构上会**触发异常或奇慢**（ARMv7 上 `uint32_t` 非对齐访问可能 HardFault）。所以优先用 ①。

## 十一、还有三个高频小坑

```c
/* ① switch 忘 break：会一直往下执行 */
switch (cmd) {
case 1: do_a();          /* 缺 break */
case 2: do_b(); break;
}

/* ② 宏的参数被求值两次 */
#define MAX(a, b) ((a) > (b) ? (a) : (b))
MAX(i++, j);             /* i++ 可能执行两次 */

/* ③ 字符串常量不可写 */
char *s = "abc";
s[0] = 'A';              /* 段错误：它在只读段 */
```

对应修法：`break` 别忘（`fallthrough` 要显式注释）、宏参数加括号且避免副作用（或改 `static inline` 函数）、字符串字面量用 `const char *`。

## 十二、一句话总结

**C 的坑几乎都围绕"内存边界、类型转换、生命周期"三件事：`free` 只认原指针、`sizeof` 只认真数组、拷贝必须判上限、有符号别和无符号混比、中断共享变量要 `volatile` 加临界区。**
